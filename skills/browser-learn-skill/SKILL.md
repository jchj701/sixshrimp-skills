# L1: 原则指导层 (WHY)

## 核心原则

> **"AI不做不确定的决策。一次性操作必须标记。环境不行不往下走。"**

1. **保守执行原则**：宁可慢一步确认，不可快一步出错
2. **可审计原则**：每个关键决策点必须有人类确认记录
3. **渐进式原则**：从低置信度逐步提升，不追求一步到位
4. **异常上报原则**：录制中的任何异常必须报告，不得跳过

---

## 🔴 AI 边界约束

> 以下条款为刚性约束，违反即触发中断。任何情况下不得绕过。

| 编号 | 禁止条款 | 触发条件 | 违规处理 |
|------|---------|---------|---------|
| 🔴 B1 | **禁止自决策** | 发现歧义按钮、模糊术语、内部概念 | 立即暂停，交互式询问用户 |
| 🔴 B2 | **禁止跳过环境检查** | 执行任何Phase前 | 环境未就绪时阻塞流程 |
| 🔴 B3 | **禁止修改原始录制** | 读取录制数据时 | AI只能读取和解读，不得改动原始数据 |
| 🔴 B4 | **禁止在低置信度时继续** | 置信度 < 0.70 | 暂停执行，等待用户指令 |
| 🔴 B5 | **禁止猜测一次性操作的复现方式** | 检测到提交/删除/状态变更操作 | 必须询问用户如何准备环境 |
| 🔴 B6 | **禁止忽略异常信号** | 录制中出现错误、时间异常、缺失数据 | 必须报告，不得跳过 |
| 🔴 B7 | **禁止在未理解时执行** | 每个操作步骤前 | 必须完成"理解确认"环节 |

## 自由度光谱

| 操作类型 | 风险等级 | AI行为模式 | 示例 |
|---------|---------|-----------|------|
| **确定性操作** | 🟢 低 | 用脚本锁死执行 | 点击固定ID按钮、输入固定文本 |
| **条件性操作** | 🟡 中 | 用脚本检查 + 文字引导 | 单选按钮切换、下拉菜单选择 |
| **创造性/判断性操作** | 🔴 高 | 用文字引导 + 必须交互确认 | 术语解读、歧义判定、置信度评估 |
| **录制清洗** | 🟢 低 | 用脚本自动化 | 去噪音、合并等待、事件去重 |
| **交互式确认** | 🔴 高 | 强制人机对话 | 歧义按钮选择、异常上报 |

## Phase 1: 可复现性评估

### 1.1 目标

判定用户演示的操作是否可以被重复执行。识别并标记**一次性操作**（提交、删除、状态变更），确保AI理解哪些操作需要特殊处理。

### 1.2 输入/输出

| 类型 | 内容 |
|------|------|
| **输入** | 录制事件流（JSON）、目标URL、用户声明的操作意图 |
| **输出** | `reproducibility_report.json`、`one_time_operations` 清单 |

### 1.3 执行步骤

**步骤 1.3.1：事件分类**

对每个操作事件按以下维度分类：

| 操作类型 | 定义 | 示例 |
|---------|------|------|
| **确定性操作** | 相同输入必定产生相同结果 | 点击确定按钮、输入固定文本 |
| **条件性操作** | 结果依赖当前状态 | 点击单选按钮、切换下拉菜单 |
| **状态变更操作** | 操作会改变系统状态 | 提交表单、删除记录 |
| **一次性操作** | 仅能执行一次 | 验证码提交、唯一性校验 |

判定细则详见 `references/reproducibility-checklist.md`。

**步骤 1.3.2：生成可复现性报告**

```json
{
    "step_id": "step_5",
    "reproducible": false,
    "confidence": 0.65,
    "reason": "检测到状态变更操作：订单提交",
    "requires_preparation": true,
    "preparation_instruction": "需要重置测试订单环境"
}
```

### 1.4 关键决策点

#### 🔴 暂停：发现一次性操作

```
⚠️ 检测到一次性操作：步骤5 - "提交订单" 按钮
📋 当前状态：订单已提交
🔄 所需状态：新订单待提交

❓ 请问如何准备测试环境？
1. 【推荐】每次执行前新建测试订单
2. 使用测试环境的演示数据
3. 其他方式（请说明）
```

## Phase 2: 环境就绪检查

### 2.1 目标

在执行前验证所有前置条件是否满足，确保环境状态适合脚本执行。

### 2.2 输入/输出

| 类型 | 内容 |
|------|------|
| **输入** | 目标URL列表、预期页面状态、登录状态、前置数据依赖 |
| **输出** | `env_readiness_report.json`、`blocker_list` |

### 2.3 执行步骤

**步骤 2.3.1：执行环境检查脚本**

调用 `scripts/env_readiness_check.py`：

```bash
python scripts/env_readiness_check.py \
    --url "https://example.com/dashboard" \
    --expected_title "仪表盘" \
    --required_elements '[{"id": "sidebar"}, {"class": "user-info"}]' \
    --login_required true
```

**步骤 2.3.2：检查清单**

| 检查项 | 检查方式 | 失败处理 |
|-------|---------|---------|
| **URL可达性** | HTTP请求测试 | 提示网络问题 |
| **页面加载** | DOM Ready状态 | 等待或重试 |
| **元素存在** | DOM查询 | 记录缺失元素 |
| **登录状态** | Cookie/Session检查 | 引导登录 |
| **数据就绪** | 前置条件验证 | 提示数据准备 |

### 2.4 关键决策点

#### 🔴 阻塞：环境未就绪

```
🛑 环境检查未通过，发现以下阻塞问题：

1. ❌ 页面元素缺失
   - 预期：存在 id="submit-btn"
   - 实际：未找到
   - 建议：确认页面已加载完成

2. ⚠️ 网络延迟较高
   - 当前延迟：3.2秒

请选择：
1. 等待页面加载后重试
2. 手动修复环境后继续
```

## Phase 3: 录制解读与交互式确认

### 3.1 目标

解析录制脚本，识别**异常**、**歧义按钮**和**内部术语**，通过交互式问答与用户确认。

### 3.2 输入/输出

| 类型 | 内容 |
|------|------|
| **输入** | 原始录制事件流（清洗后）、页面DOM快照 |
| **输出** | `interpreted_script.json`、`ambiguity_resolution_log` |

### 3.3 执行步骤

**步骤 3.3.1：脚本清洗**

调用 `scripts/script_sanitize.py`：

```bash
python scripts/script_sanitize.py \
    --input recording_raw.json \
    --output recording_clean.json \
    --remove_mouse_moves true \
    --merge_wait_events true
```

清洗规则详见 `references/script-format-spec.md`。

**步骤 3.3.2：异常识别**

标记以下异常类型：

| 异常类型 | 检测规则 | 标记字段 |
|---------|---------|---------|
| **元素不稳定** | 动态ID、随机class | `selector_unstable: true` |
| **操作副作用** | 触发副作用的操作 | `has_side_effect: true` |
| **时间依赖** | 依赖时序的操作 | `timing_critical: true` |

**步骤 3.3.3：歧义识别**

歧义类型清单：
- **按钮文本歧义**：模糊文本如"确定"、"继续"、"下一步"
- **选择器歧义**：多个元素匹配同一选择器
- **操作意图歧义**：同一操作可达成多个结果
- **内部术语**：业务特有术语、非标准UI组件

### 3.4 关键决策点

#### 🟡 交互确认：歧义按钮

```
🔍 步骤3 存在歧义需要确认：

📍 操作：点击按钮
🎯 选择器：button.primary

⚠️ 发现歧义：
页面中存在多个匹配元素：
1. [0] "确定" 按钮 - 提交表单
2. [1] "确定" 按钮 - 关闭弹窗

❓ 请确认您要点击的是哪一个？
```

#### 🟡 交互确认：内部术语

```
📝 步骤4 包含内部术语需要解释：

🔤 术语："走流程"
❓ 这是什么意思？
   - A：点击"发起流程"按钮
   - B：进入流程审批页面
   - C：执行预设的审批流程
```

### 3.5 输出格式

解析完成后生成 `interpreted_script.json`，详见 `references/script-format-spec.md` 第5节。

## Phase 4: 执行与置信度检测

### 4.1 目标

实际执行脚本，实时评估执行置信度，在低置信度时采取适当行动。

### 4.2 输入/输出

| 类型 | 内容 |
|------|------|
| **输入** | 已解读脚本（`interpreted_script.json`）、执行策略配置 |
| **输出** | `execution_log.json`、`confidence_trajectory`、`final_verdict` |

### 4.3 执行步骤

**步骤 4.3.1：执行前置信度预览**

```
┌────────────────────────────────────────────────────┐
│              置信度预览报告                           │
├────────────────────────────────────────────────────┤
│  总体置信度：0.78                                    │
│  风险等级：🟡 中等                                  │
│                                                    │
│  高风险点：                                          │
│  ⚠️ 步骤5：提交按钮可能因页面更新而变化               │
│  ⚠️ 步骤8：依赖动态加载的数据列表                     │
│                                                    │
│  ❓ 是否继续执行？                                   │
│  1. 继续执行（AI自主执行）                           │
│  2. 保守执行（降低速度，发现异常暂停）                │
│  3. 人工监督（每步确认）                              │
└────────────────────────────────────────────────────┘
```

**步骤 4.3.2：分步执行与实时监控**

每步执行时记录指标：

```json
{
    "step_id": 5,
    "element_found": true,
    "expected_result_matched": true,
    "confidence_delta": -0.05,
    "warnings": []
}
```

**步骤 4.3.3：置信度阈值响应**

| 置信度区间 | AI行为 | 描述 |
|-----------|--------|------|
| **≥ 0.90** | 正常执行 | AI自主执行 |
| **0.70 - 0.89** | 谨慎执行 | 执行后短暂停顿确认 |
| **0.50 - 0.69** | 人工确认 | 每步执行前询问 |
| **< 0.50** | 暂停回退 | 暂停，等待指令 |

置信度评分细则详见 `references/confidence-scoring.md`。

### 4.4 关键决策点

#### 🔴 置信度骤降

```
⚠️ 置信度骤降至 0.45

📍 步骤7 - 点击"下一步"按钮
🕐 时间：10:35:23

📉 变化原因：
- 预期：点击后跳转到确认页面
- 实际：页面无响应

🔄 建议操作：
1. 【自动恢复】尝试语义定位
2. 【回退重试】返回步骤6重新执行
3. 【暂停等待】等待人工判断

请选择：
```

## Phase 5: 固化与演进

### 5.1 目标

根据执行置信度决定是否固化脚本，支持渐进式固化。

### 5.2 固化等级

| 等级 | 名称 | 置信度要求 | 特征 |
|------|------|-----------|------|
| **L1** | 草稿态 | 0.0 - 0.59 | 需人工监督执行 |
| **L2** | 可执行态 | 0.60 - 0.74 | AI执行，发现问题暂停 |
| **L3** | 稳定态 | 0.75 - 0.89 | AI自主执行，异常时自恢复 |
| **L4** | 固化态 | 0.90 - 1.00 | 完全固化，可独立运行 |

### 5.3 升级条件

详见 `references/solidification-criteria.md`。

| 升级路径 | 连续成功 | 平均置信度 | 其他要求 |
|---------|---------|-----------|---------|
| L1 → L2 | 3次 | ≥ 0.65 | 无关键异常 |
| L2 → L3 | 10次 | ≥ 0.80 | 自恢复成功≥3 |
| L3 → L4 | 50次 | ≥ 0.92 | 最近30次无失败 |

### 5.4 关键决策点

#### 🟢 达到固化条件

```
🎉 恭喜！技能已达到固化条件

📊 固化评估报告：
├── 当前等级：L3 → L4
├── 连续成功：50次
├── 平均置信度：0.94
└── 自恢复成功：12次

✅ 固化产物：
- 位置：~/.browser-learn/skills/登录XX系统_v4.py
```

#### 🔴 固化失败

```
⚠️ 固化条件未满足

📊 当前状态：
├── 当前等级：L2
├── 连续成功：2次（需要3次）
└── 关键问题：步骤5稳定性不足

🔧 建议操作：
1. 继续演进（执行更多迭代）
2. AI分析优化脚本
3. 重新录制新演示
```
