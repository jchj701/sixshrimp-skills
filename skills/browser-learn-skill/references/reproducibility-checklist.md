# 可复现性判定清单

本文档定义 AI Agent 如何判定用户演示的操作是否具有可复现性。

---

## 1. 操作分类体系

### 1.1 五大操作类型

| 类型 | 代码 | 定义 | 可复现性 |
|------|------|------|---------|
| **确定性操作** | DETERMINISTIC | 相同输入必定产生相同结果 | ✅ 完全可复现 |
| **条件性操作** | CONDITIONAL | 结果依赖当前状态 | ⚠️ 条件可复现 |
| **状态变更操作** | STATE_CHANGE | 操作会改变系统状态 | ⚠️ 需状态管理 |
| **一次性操作** | ONE_TIME | 仅能执行一次 | ❌ 不可复现 |
| **环境依赖操作** | ENV_DEPENDENT | 需要特定前置条件 | ⚠️ 需环境准备 |

### 1.2 操作类型详细说明

#### 确定性操作（DETERMINISTIC）

**定义**：无论何时执行，只要输入相同，结果必然相同。

**典型示例**：

| 操作 | 描述 | 可复现性理由 |
|------|------|-------------|
| 点击确定按钮 | UI按钮点击总是有效 | 完全可复现 |
| 输入固定文本 | 文本输入总是成功 | 完全可复现 |
| 页面导航 | URL访问通常可靠 | 完全可复现 |
| 滚动页面 | 滚动操作无副作用 | 完全可复现 |

**判定规则**：
```
IF 操作不改变数据
AND 操作不依赖外部状态
AND 操作不触发副作用
THEN 标记为 DETERMINISTIC
```

#### 条件性操作（CONDITIONAL）

**定义**：操作结果依赖于页面或系统的当前状态。

**典型示例**：

| 操作 | 依赖状态 | 风险点 |
|------|---------|--------|
| 选择下拉选项 | 当前选中的选项 | 重复选择可能无效 |
| 点击复选框 | 当前勾选状态 | toggle行为 |
| 展开折叠面板 | 当前展开状态 | 重复操作效果相反 |
| 筛选数据列表 | 当前筛选条件 | 结果数量变化 |

**判定规则**：
```
IF 操作效果依赖于元素当前状态
AND 状态可能在执行时不同
THEN 标记为 CONDITIONAL
AND 要求验证前置状态
```

#### 状态变更操作（STATE_CHANGE）

**定义**：操作会永久改变系统状态，产生不可逆影响。

**典型示例**：

| 操作 | 状态变化 | 影响 |
|------|---------|------|
| 提交表单 | 创建新记录 | 数据库写入 |
| 删除记录 | 数据被删除 | 不可恢复 |
| 发送消息 | 消息已发送 | 可能无法撤回 |
| 支付订单 | 资金流转 | 金融影响 |
| 修改配置 | 系统配置变更 | 影响后续操作 |

**判定规则**：
```
IF 操作会修改数据库
OR 操作会触发外部系统变化
OR 操作不可撤销
THEN 标记为 STATE_CHANGE
AND 要求确认测试环境
```

#### 一次性操作（ONE_TIME）

**定义**：操作在相同上下文只能执行一次，再次执行需要重置。

**典型示例**：

| 操作 | 一次性原因 | 重置方式 |
|------|----------|---------|
| 验证码提交 | 验证码过期 | 获取新验证码 |
| 邀请链接点击 | 已加入组织 | 需新邀请 |
| 注册提交 | 用户已存在 | 需新账号 |
| 唯一性检查 | 检查结果缓存 | 需新数据 |
| 文件上传 | 文件已存在 | 需新文件 |

**判定规则**：
```
IF 操作触发唯一性校验
OR 操作依赖临时凭证
OR 操作消耗稀缺资源
THEN 标记为 ONE_TIME
AND 要求每次执行前重置
```

#### 环境依赖操作（ENV_DEPENDENT）

**定义**：操作需要特定的前置环境条件。

**典型示例**：

| 操作 | 环境依赖 | 准备方式 |
|------|---------|---------|
| 上传附件 | 文件存在 | 准备测试文件 |
| 选择数据 | 数据存在 | 创建测试数据 |
| 审批操作 | 有待审批项 | 准备测试流程 |
| 评论操作 | 登录状态 | 保持会话有效 |

**判定规则**：
```
IF 操作需要特定数据存在
OR 操作需要登录会话
OR 操作需要网络/资源可用
THEN 标记为 ENV_DEPENDENT
AND 要求验证环境就绪
```

## 2. 判定流程

### 2.1 判定决策树

```
开始判定
    │
    ▼
┌─────────────────────────┐
│ 操作用于数据创建/修改？    │
└───────────┬─────────────┘
            │
     ┌──────┴──────┐
     │YES          │NO
     ▼             ▼
┌─────────┐  ┌─────────────────────┐
│STATE_   │  │ 操作依赖临时凭证/    │
│CHANGE   │  │ 一次性资源？         │
└────┬────┘  └──────────┬──────────┘
     │           ┌─────┴─────┐
     │           │YES        │NO
     │           ▼           ▼
     │    ┌──────────┐  ┌─────────────────┐
     │    │ ONE_TIME │  │ 操作效果依赖    │
     │    └────┬─────┘  │ 当前元素状态？  │
     │         │        └────────┬────────┘
     │         │          ┌─────┴─────┐
     │         │          │YES        │NO
     │         │          ▼           ▼
     │    ┌─────────┐ ┌─────────┐ ┌─────────────┐
     │    │CONDI-   │ │DETER-   │ │ENV_DE-      │
     │    │TIONAL   │ │MINISTIC │ │PENDENT      │
     │    └─────────┘ └─────────┘ └─────────────┘
     │
     ▼
检查是否需要状态管理
```

### 2.2 判定检查清单

#### Step 1: 数据影响检查

- [ ] 操作是否创建新数据？
- [ ] 操作是否修改现有数据？
- [ ] 操作是否删除数据？
- [ ] 操作是否触发外部系统调用？

#### Step 2: 唯一性检查

- [ ] 操作是否使用一次性验证码？
- [ ] 操作是否检查唯一性约束？
- [ ] 操作是否消耗不可重复资源？
- [ ] 操作结果是否被缓存？

#### Step 3: 状态依赖检查

- [ ] 操作效果是否依赖元素当前状态？
- [ ] 操作是否可能是 toggle 行为？
- [ ] 连续执行两次会产生什么效果？

#### Step 4: 环境要求检查

- [ ] 操作是否需要特定数据存在？
- [ ] 操作是否需要登录状态？
- [ ] 操作是否需要网络连接？
- [ ] 操作是否需要特定文件/资源？

## 3. 可复现性评估矩阵

### 3.1 按页面类型分类

| 页面类型 | 典型操作 | 可复现性评估 |
|---------|---------|-------------|
| **只读页面** | 浏览、搜索、筛选 | ✅ 高可复现性 |
| **表单页面** | 输入、选择、提交 | ⚠️ 中可复现性（取决于提交后状态） |
| **数据管理页面** | CRUD操作 | ❌ 低可复现性（修改类） |
| **工作流页面** | 审批、流转 | ⚠️ 取决于流程状态 |
| **动态内容页面** | 实时数据、通知 | ⚠️ 受外部数据影响 |

### 3.2 按操作类型分类

| 操作类型 | 可复现性 | 风险因素 | 缓解措施 |
|---------|---------|---------|---------|
| `click` | 高-中 | 状态依赖 | 检查元素状态 |
| `type` | 高 | 无 | 使用固定值 |
| `select` | 中 | 当前选项 | 明确选择逻辑 |
| `submit` | 低 | 状态变更 | 测试环境 |
| `delete` | 低 | 不可逆 | 确认提示 |
| `upload` | 中 | 文件存在 | 准备文件 |
| `navigate` | 高 | URL有效 | 检查URL |

### 4.1 一次性操作准备

```markdown
## [操作名称] 环境准备指令

### 当前问题
[描述为什么需要准备]

### 目标状态
[描述需要达到的状态]

### 准备步骤
1. [步骤1]
2. [步骤2]
3. [步骤3]

### 验证方法
[如何确认环境已就绪]

### 自动化建议
[如果可以，提供自动化准备脚本的建议]
```

### 4.2 示例：订单提交操作

```markdown
## 订单提交 环境准备指令

### 当前问题
订单提交是状态变更操作，提交后该订单状态变为"已处理"，
无法再次提交相同订单。

### 目标状态
- 系统中有待提交的测试订单
- 订单处于"待处理"状态
- 订单金额和商品信息符合测试要求

### 准备步骤
1. 打开订单管理页面
2. 点击"新建订单"按钮
3. 填写测试订单信息（订单号: TEST-001）
4. 点击"保存"生成待提交订单

### 验证方法
- 在订单列表中能看到状态为"待处理"的 TEST-001 订单
- 订单金额显示为测试金额

### 自动化建议
- 创建测试数据 fixture
- 每次执行前通过 API 创建新订单
- 或使用数据库回滚机制
```

## 5. 风险标记系统

### 5.1 风险级别定义

| 风险级别 | 标识 | 含义 | AI行为 |
|---------|------|------|--------|
| **低风险** | 🟢 | 无特殊风险，可正常执行 | 正常执行 |
| **中风险** | 🟡 | 存在潜在风险，需要注意 | 执行后确认 |
| **高风险** | 🔴 | 存在明确风险，需准备环境 | 执行前暂停 |
| **禁止** | ⛔ | 不应执行的操作 | 拒绝执行 |

### 5.2 风险判定规则

```python
def assess_risk(operation, context):
    risk_level = "LOW"
    warnings = []
    blockers = []
    
    # 检查是否修改数据
    if operation.is_state_change:
        risk_level = "HIGH"
        warnings.append("此操作会修改系统状态")
        blockers.append("需要确认测试环境")
    
    # 检查是否一次性操作
    if operation.is_one_time:
        risk_level = "HIGH"
        warnings.append("此操作只能执行一次")
        blockers.append("需要重置环境")
    
    # 检查环境依赖
    if not context.environment_ready:
        risk_level = max(risk_level, "MEDIUM")
        warnings.append("环境可能未就绪")
        blockers.append("需要检查环境")
    
    # 检查数据依赖
    if operation.requires_data and not context.data_exists:
        risk_level = "HIGH"
        warnings.append("所需数据不存在")
        blockers.append("需要准备测试数据")
    
    return {
        "level": risk_level,
        "warnings": warnings,
        "blockers": blockers,
        "requires_confirmation": risk_level in ["MEDIUM", "HIGH"]
    }
```

## 7. 常见场景判定示例

### 场景 1：用户登录

| 步骤 | 操作 | 类型 | 判定 | 理由 |
|------|------|------|------|------|
| 1 | 输入用户名 | DETERMINISTIC | ✅ 可复现 | 固定输入 |
| 2 | 输入密码 | DETERMINISTIC | ✅ 可复现 | 固定输入 |
| 3 | 点击登录按钮 | DETERMINISTIC | ✅ 可复现 | 通常可重复 |
| 4 | 等待跳转 | CONDITIONAL | ⚠️ 条件可复现 | 依赖登录成功 |

### 场景 2：发布文章

| 步骤 | 操作 | 类型 | 判定 | 理由 |
|------|------|------|------|------|
| 1 | 点击新建文章 | STATE_CHANGE | ⚠️ 创建草稿 | 可能需检查草稿是否存在 |
| 2 | 填写标题 | DETERMINISTIC | ✅ 可复现 | 无副作用 |
| 3 | 填写内容 | DETERMINISTIC | ✅ 可复现 | 无副作用 |
| 4 | 点击发布 | STATE_CHANGE | 🔴 高风险 | 发布后状态变更 |
| 5 | 确认发布 | ONE_TIME | ⛔ 禁止复现 | 已发布的文章不能重复发布 |

### 场景 3：数据导出

| 步骤 | 操作 | 类型 | 判定 | 理由 |
|------|------|------|------|------|
| 1 | 选择日期范围 | CONDITIONAL | ⚠️ 当前选中状态 | toggle行为 |
| 2 | 选择导出格式 | DETERMINISTIC | ✅ 可复现 | 无副作用 |
| 3 | 点击导出按钮 | ENV_DEPENDENT | ⚠️ 依赖数据 | 范围内无数据则失败 |
| 4 | 等待下载 | DETERMINISTIC | ✅ 可复现 | 只读操作 |
