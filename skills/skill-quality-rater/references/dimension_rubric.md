# 各维度详细评分细则

> 本文档提供8个维度的详细评分标准

---

## D1. 触发精准度 (权重15%)

### 检查点
- description是否包含"when to use"？
- 触发条件是否在frontmatter？
- 触发词是否与其他Skill冲突？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | description完整含when to use，触发词无冲突 |
| 7-8 | 基本完整 |
| 5-6 | 缺少when to use |
| 3-4 | 触发条件在body |
| <3 | 严重缺失 |

### 典型扣分
- description只说"做什么"不说"什么时候用" → -2分
- 触发条件写在body而非frontmatter → -3分

---

## D2. 分层合理性 (权重20%)

### 检查点
- L1层(原则)是否在SKILL.md顶部？
- L2层(操作)是否清晰？
- L3层(参考)是否在references/？
- 有无层错位？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | L1/L2/L3完美分层 |
| 7-8 | 基本正确 |
| 5-6 | 有层错位 |
| <5 | 完全混乱 |

### 典型扣分
- 参考细节塞进SKILL.md → -2分
- 确定性操作写成文字 → -3分

---

## D3. 自由度匹配 (权重20%)

### 检查点
- 脆弱操作(文件IO、API)是否脚本化？
- 创造性任务是否过度约束？
- 是否判断"该用哪种"？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 脆弱操作全部脚本化，创造性任务保持自由 |
| 7-8 | 基本匹配 |
| 5-6 | 有缺失或过度约束 |
| <5 | 完全没考虑 |

### 典型扣分
- 脆弱操作没脚本 → -3分
- 创造性任务过度约束 → -2分

---

## D4. 简洁约束 (权重15%)

### 检查点
- 是否有禁止文件(README.md等)？
- 每句话是否值得token？
- 是否有冗余解释？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 无冗余 |
| 7-8 | 基本简洁 |
| 5-6 | 有冗余 |
| <5 | 大量冗余 |

### 禁止文件
- README.md (-2分)
- CHANGELOG.md (-2分)
- TODO.md (-1分)

---

## D5. 反模式表达 (权重10%)

### 检查点
- 是否有"不做什么"说明？
- 反模式是否比正面描述更具体？
- 边界情况是否处理？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 反模式清晰完整 |
| 7-8 | 有但不全面 |
| 5-6 | 只有正面描述 |
| <5 | 完全无反模式 |

### 典型扣分
- 只有正面描述无反模式 → -2分

---

## D6. 资源组织 (权重10%)

### 检查点
- scripts/是否只包含可执行脚本？
- references/是否只包含参考资料？
- 是否有内容重复？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 三类资源完全分离 |
| 7-8 | 基本正确 |
| 5-6 | 有混淆或重复 |
| <5 | 完全混乱 |

---

## D7. 领域适配 (权重5%)

### 检查点
- 是否符合领域最佳实践？
- 是否有领域特定规则？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 完全符合 |
| 7-8 | 基本符合 |
| <7 | 有偏差 |

---

## D8. 安全边界 (权重5%)

### 检查点
- 是否有危险命令？
- 是否有敏感信息泄露？

### 评分标准

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 无安全问题 |
| 7-8 | 基本安全 |
| <7 | 有安全隐患 |

---

## 综合评分计算

```
总分 = Σ(维度得分 × 权重)

等级：
- S级：9.0-10
- A级：8.0-8.9
- B级：7.0-7.9
- C级：6.0-6.9
- D级：<6.0
```
