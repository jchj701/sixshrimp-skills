# 自由度光谱判断指南

> **原文核心创新**：本工具首创的评估维度，所有现有工具均未实现

---

## 核心概念

自由度光谱描述了一个任务需要的"约束程度"：

```
低自由度 ════════════════════════════ 高自由度
    │                                    │
    ▼                                    ▼
确定性操作                          创造性任务
（必须精确执行）                    （允许自由发挥）
```

### 两条黄金法则

1. **脆弱操作 → 用脚本锁定**
   > 如果一个操作容易出错（文件IO、路径处理、格式转换），必须用脚本封装
   > 因为文字描述无法覆盖所有边界情况

2. **创造性任务 → 用原则约束**
   > 如果一个任务需要AI自由发挥（写文案、做设计），不要过度约束
   > 因为过度约束会限制AI的能力

---

## 操作类型分类

### 🔴 必须用脚本的操作（低自由度）

| 操作类型 | 原因 | 典型示例 |
|:---|:---|:---|
| 文件读取 | 路径可能不存在、权限可能不足 | `read_file(path)` |
| 文件写入 | 可能目录不存在、磁盘可能满 | `write_file(path, content)` |
| 文件删除 | 不可逆操作，必须精确 | `rm(path)` |
| 目录创建 | 父目录可能不存在 | `mkdir(path)` |
| API调用 | 网络可能超时、可能返回错误 | `fetch_api(url)` |
| 格式化转换 | 规则复杂，容易出错 | JSON→CSV、Markdown→HTML |
| 参数解析 | 边界情况多 | 命令行参数处理 |
| 编码处理 | 字符集问题 | UTF-8/GBK转换 |

### 🟡 可以用文字但建议脚本的操作

| 操作类型 | 原因 | 建议 |
|:---|:---|:---|
| 数据验证 | 规则简单时可用文字 | 简单正则可用文字 |
| 简单计算 | 公式简单时可用文字 | 复杂计算用脚本 |
| 文本替换 | 规则明确时可用文字 | 大规模替换用脚本 |

### 🟢 建议用文字的操作（高自由度）

| 操作类型 | 原因 | 示例 |
|:---|:---|:---|
| 文案生成 | 需要创意和灵活性 | 产品介绍、营销文案 |
| 方案设计 | 需要根据情况调整 | 解决方案、技术架构 |
| 代码编写 | 需要理解上下文 | 实现某个功能 |
| 风格把控 | 需要灵活处理 | 语气、表达方式 |
| 问题分析 | 需要推理和判断 | 原因分析、诊断 |

## 自由度判断流程

```
开始判断
    │
    ▼
这个操作是否容易出错？
    │
    ├─ 是 ──→ 这个操作是否需要AI自由发挥？
    │              │
    │              ├─ 是 ──→ 用"原则约束"
    │              │           示例：允许AI根据用户语气调整表达
    │              │
    │              └─ 否 ──→ 用"脚本锁定"
    │                          示例：脚本处理所有边界情况
    │
    └─ 否 ──→ 这个操作是否复杂？
                  │
                  ├─ 是 ──→ 用"脚本"
                  │
                  └─ 否 ──→ 可用"文字"简述
```

## 典型问题分析

### ❌ 问题1：脆弱操作没脚本

**场景**：PDF提取Skill的文字说明

```markdown
## 步骤
1. 检查文件是否存在
2. 打开PDF文件
3. 读取每一页内容
4. 如果遇到加密，返回"文件已加密"
5. 如果遇到损坏，返回"文件损坏"
6. 提取文本和表格
7. 关闭文件
```

**问题**：
- 路径不存在怎么办？
- 权限不足怎么办？
- 内存不足怎么办？
- 1000页的PDF怎么处理？

**扣分**：-3分（脆弱操作没脚本）

**正确做法**：
```markdown
## 步骤
1. 调用 `scripts/extract.py input.pdf` 提取内容
2. 脚本自动处理所有边界情况
```

```python
# scripts/extract.py
import sys
import os

def main():
    path = sys.argv[1] if len(sys.argv) > 1 else "input.pdf"
    
    # 自动创建输出目录
    os.makedirs("output", exist_ok=True)
    
    # 脚本处理所有边界情况
    # ...
```

### ❌ 问题2：创造性任务过度约束

**场景**：文案生成Skill

```markdown
## 文案生成规则
1. 第一段不超过20字
2. 第二段必须包含关键词"高效"
3. 第三段必须包含关键词"专业"
4. 第四段必须包含关键词"值得信赖"
5. 全文使用主动语态
6. 全文使用第二人称"你"
7. 避免使用程度副词"非常"、"特别"
8. 避免使用感叹句
9. 避免使用疑问句
10. 结尾必须是"选择我们"
```

**问题**：
- 这是在让AI写文案，还是在让AI填表格？
- AI的创意能力被完全压制
- 用户可能得到的是机械的套话

**扣分**：-2分（创造性任务过度约束）

**正确做法**：
```markdown
## 风格指导
- 简洁有力，避免套话
- 核心卖点准确传达
- 允许AI根据用户语气调整表达方式
- 具体形式由AI根据场景判断
```

### ❌ 问题3：确定性操作写成冗长文字

**场景**：数据验证Skill

```markdown
## 验证步骤
首先，检查输入是否为字符串类型。如果不是，抛出类型错误。
然后，检查字符串长度是否在1到1000之间。如果小于1，说明输入为空。
如果大于1000，需要截断到前1000个字符。
接着，检查是否包含特殊字符。如果包含，记录警告但不中断。
最后，检查是否匹配预期格式。如果不匹配，返回格式错误信息。
```

**问题**：
- 300字说明一个简单的验证逻辑
- 应该用脚本，10行代码搞定

**扣分**：-2分（确定性操作写成冗长文字）

**正确做法**：
```markdown
## 验证流程
调用 `scripts/validate.py` 进行验证，脚本自动处理：
- 类型检查
- 长度限制（1-1000）
- 特殊字符处理
- 格式校验
```

## 评估检查清单

### 必须检查的项目

- [ ] **文件操作**（读写删）是否全部脚本化？
- [ ] **API调用**是否封装成脚本？
- [ ] **格式转换**是否用脚本处理？
- [ ] **创造性任务**是否避免了过度约束？

### 扣分速查

| 情况 | 扣分 | 严重程度 |
|:---|:---:|:---:|
| 脆弱操作（文件IO）没脚本 | -3分 | 🔴严重 |
| 确定性操作写成冗长文字 | -2分 | 🟠较重 |
| 创造性任务过度约束 | -2分 | 🟠较重 |
| 脚本参数过多 | -1分 | 🟡一般 |

## 评分细则

### D3. 自由度匹配 (权重20%)

| 得分 | 表现 |
|:---:|:---|
| 9-10 | 脆弱操作全部脚本化，创造性任务保持自由度 |
| 7-8 | 基本匹配，个别可以优化 |
| 5-6 | 有脚本但覆盖不全，或过度约束 |
| 3-4 | 脆弱操作没脚本，或创造性任务被过度约束 |
| 0-2 | 完全没考虑自由度问题 |

### 评分计算

```
维度得分 = 10 - Σ(各类问题扣分)

例如：
- 文件IO没脚本: -3分
- 格式转换没脚本: -2分
- 创造性任务过度约束: -1分
------------------------
最终得分: 10 - 6 = 4分
```
